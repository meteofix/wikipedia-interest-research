# Evals: як перевіряємо навичку на дешевій моделі

Тут лежать набори питань, скрипт прогону агента (`run_evals.py`) і оцінювач (`grade.py`). Критерії та пороги зафіксовано в [`docs/ACCEPTANCE.md`](../docs/ACCEPTANCE.md) до реалізації; тут описано, як їх міряти.

## Набори

| Набір | Де лежить | Хто написав | Як використовується |
|---|---|---|---|
| робочий (`dev`) | `evals/dev.jsonl` | окремий агент за [таксономією](taxonomy.md) і [схемою розмітки](label_schema.md) + 3 публічні приклади з умови | вільно, на кожній ітерації |
| прихований (`heldout`) | поза репозиторієм: `../../pes_task_1_private/heldout/heldout.jsonl`; тут лише `heldout.sha256` | окремий агент, який бачив тільки текст умови (без таксономії й без репозиторію) | ≤ 2 запуски за проєкт, видно лише агрегати |
| базова лінія | робочий набір, прапорець `--no-skill` | — | та сама модель без навички, для порівняння |

Шлях до приватної директорії обчислюється відносно репозиторію (`<батьківська тека>/<назва репо>_private`); його можна перевизначити змінною `WIKI_EVAL_PRIVATE`.

## Запуск

Команди виконуються з директорії навички (`wikipedia-interest-research/`). Потрібні `uv` і `claude` (Claude Code, залогінений).

```bash
# робочий набір, Claude Haiku 4.5 з навичкою
uv run evals/run_evals.py --set dev --iteration it1
uv run evals/grade.py     --set dev --iteration it1

# базова лінія: та сама модель без навички на 15 питаннях
uv run evals/run_evals.py --set dev --no-skill --limit 15 --iteration it1
uv run evals/grade.py     --set dev --iteration it1          # у звіті з'явиться таблиця «з навичкою / без»

# прихований набір: 2 прогони на питання, друкуються лише агрегати
uv run evals/run_evals.py --set heldout --runs 2 --iteration heldout-1
uv run evals/grade.py     --set heldout --iteration heldout-1

# корисні прапорці
#   --ids dev-001,dev-d02   --limit N   --parallel 4   --timeout 600   --force
#   grade.py --no-judge (лише автоматичні перевірки)   --judge-model sonnet
```

Результати:
- **Сирі прогони** — `<private>/eval-runs/<iteration>/<config>/<item>/run<k>/`:
  - `project/` — робоча тека агента;
  - `outputs/` — аналізи навички;
  - `transcript.jsonl`, `result.json`, `grade.json`.
- **Агрегати** — `<private>/eval-runs/<iteration>/grades.json` і `summary.md`.
- **Публічний звіт** — `evals/results/<iteration>.md`. Для робочого набору він містить таблицю по кожному прогону, для прихованого — лише агреговані числа.

## Як ізольовано кожен прогін

- Агент запускається як `claude -p … --model haiku --setting-sources project` у власній теці `project/`. Налаштування користувача, сторонні навички й плагіни не підвантажуються.
- У `project/.claude/skills/wikipedia-interest-research/` копіюється лише runtime-частина навички: `SKILL.md`, `scripts/`, `references/`, `assets/`. Розмітки evals, тестів і документації агент не бачить.
- Дозволені інструменти: `Bash Read Write Edit Glob Grep Skill`.
- Кожен прогін отримує окрему теку результатів (`WIKI_INTEREST_OUT`).
- Кеш Wikimedia (`WIKI_INTEREST_CACHE`) спільний, щоб не навантажувати API.
- Частота запитів ділиться між паралельними агентами: `WIKI_MAX_RPS = 3 / parallel`.
- Діалоги продовжуються через `--resume <session_id>`.
- Контакт для User-Agent береться з `WIKI_CONTACT` або з `~/.zshrc` і вирізається з усіх збережених файлів. Якщо навичка записала його у свої виходи, це фіксується в `result.json → leaks`.

## Що міряємо

**Універсальні перевірки.** Однакові для кожного прогону, від конкретного питання не залежать:

| # | Перевірка | Як |
|---|---|---|
| U1 | використано навичку | виклик `scripts/wiki.py` або `Skill` (для `noskill` — n/a) |
| U2 | агент не писав власного коду для даних | автоматично: `python -c` чи heredoc, запис `.py`, `curl`/`wget` до Wikimedia, `pip install`, власні скрипти, обчислення через `awk`/`bc` |
| U3 | числа у відповіді є у виводі інструментів | автоматичний фільтр (`scripts/wikiinterest/numbers.py`). Якщо він спрацював, суддя вирішує, чи це вигадані дані |
| U4 | названо вікно даних і рівень довіри | суддя; лише коли був аналіз |
| U5 | є припущення або обмеження | суддя |
| U6 | немає тверджень про готовність платити чи про країни без застереження | суддя |
| U7 | запитані артефакти валідні | автоматично: PDF рівно на 1 сторінку (pypdf), графік є |
| U8 | відповідь мовою користувача | суддя + дешева автоматична перевірка для uk/en |

**Успіх задачі.** LLM-суддя (за замовчуванням Sonnet) отримує розмітку питання, фінальні відповіді й стислий слід викликів інструментів. Для кожного «так» він мусить навести цитату-доказ. Успіх задачі — це відповідь по суті, **усі** очікувані поведінки виконано, жодної забороненої і коректне уточнення. `grade.py` перераховує успіх зі складових, щоб суперечлива відповідь судді не завищила результат.

**Відповідність критеріям з `ACCEPTANCE.md`:**

| Критерій | Де в звіті |
|---|---|
| C1 | `fabricated numbers` — вигадані числа, підтверджені суддею |
| C2 | `all universal checks` з інтервалом Вілсона |
| C3, C4 | `task success` на прихованому і робочому наборах |
| C5 | `stability` — однаковий набір пар «(тема, мова) → напрям» з `results.json` у двох прогонах |
| C6 | `partial/out-of-scope success` — для робочого набору, за `taxonomy.scope` |
| C7 | таблиця «Skill vs no skill» |
| C8 | медіана викликів інструментів і часу на одноходових питаннях |
| C9 | `API fetches in follow-up turns` — із рядка `cache: hits=H fetched=F`, який друкує `scripts/wiki.py` |

## Секретність прихованого набору

- Файл із питаннями лежить поза репозиторієм; у репозиторії — лише його SHA-256.
- Автор набору бачив тільки текст умови.
- У режимі `--set heldout` обидва скрипти друкують тільки лічильники й агрегати. У `evals/results/<iteration>.md` потрапляють лише зведені таблиці, без зрізів і без рядків по окремих питаннях.
- Деталі лишаються в приватній теці, і під час розробки їх не читаємо.
- Після фінального прогону набір і результати публікуються в `evals/`.

## Застереження

- **Суддя — LLM, тож він може помилятися.** Тому кожне рішення має супроводжуватися цитатою, а успіх перераховується зі складових. Людський погляд на вибіркові прогони лишається частиною процесу.
- **Автоматичний фільтр чисел не вважає цілі 1990–2040 даними, бо сприймає їх як роки.** Наприклад, «2000 переглядів» він не позначить. Такі випадки ловить суддя.
- **Прогони йдуть через підписку Claude Code, а не через API.** Колонка вартості показує умовну ціну, яку повідомляє CLI.
- **Реальні дані змінюються щодня.** Прогони в різні дні можуть давати різні числа; стабільність порівнюється в межах однієї ітерації.
