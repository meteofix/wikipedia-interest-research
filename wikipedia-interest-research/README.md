# wikipedia-interest-research

Навичка ([Agent Skills](https://agentskills.io/specification)) для AI-агента. Вона допомагає засновникам B2C-продуктів вирішувати, які теми розвивати і якими мовами запускатися. Для цього навичка аналізує перегляди Вікіпедії з [Wikimedia Pageviews API](https://doc.wikimedia.org/generated-data-platform/aqs/analytics-api/reference/page-views.html) і відповідає на три питання: чи росте інтерес, наскільки цьому можна довіряти, яка мова чи тема перспективніша. На виході — відповідь у чаті, графіки і PDF-звіт на одну сторінку.

Навичка спроєктована під дешеву модель (перевірено на Claude Haiku 4.5): уся робота з даними — у коді, агент лише розуміє запит і пояснює результат.

## Що вміє

Приклади запитів (будь-які теми, мови й критерії):

- «Чи зростає інтерес до шахів у турецькій, в'єтнамській та індонезійській Вікіпедії? Куди локалізувати застосунок?»
- «Compare interest in yoga across German, French and Spanish Wikipedia over the last two years and make a one-page PDF.»
- «Коли пік інтересу до садівництва в польській Вікіпедії? Коли запускати кампанію?»
- «Що зараз найпопулярніше в чеській Вікіпедії про здоров'я?»
- Уточнення після першої відповіді: «додай словацьку», «візьми 3 роки», «без редиректів», «нас цікавлять лише мови з ростом > 15%».

Що отримує користувач:
- пряму відповідь;
- таблицю по мовах/темах: перегляди на день, частка, відносний ріст з 95%-інтервалом, напрям, **рівень довіри з причинами**;
- припущення й обмеження;
- графіки (тренд, ріст з інтервалами) і PDF на одну сторінку (українською або англійською).

## Встановлення

Потрібні Python 3.10+, [uv](https://docs.astral.sh/uv/) і доступ до `wikimedia.org` / `wikidata.org`.

```bash
# Claude Code: особиста навичка (або .claude/skills/ у проєкті)
cp -r wikipedia-interest-research ~/.claude/skills/

# Рекомендовано: контакт для User-Agent Wikimedia (без нього API обмежує ~10 запитів/хв)
export WIKI_CONTACT="you@example.com"
```

Перевірка з директорії навички: `uv run scripts/wiki.py --help`. Перший запуск встановлює залежності (~10 с, версії зафіксовано в `scripts/wiki.py.lock`).

Без uv: `pip install -r requirements.txt`, далі `python3 scripts/wiki.py …`.

Навичка працює в будь-якому агенті з підтримкою Agent Skills. Потрібні лише запуск shell-команд і читання файлів.

## Як це працює

```
запит → [LLM] теми, мови, період, критерії
      → find     тема → елемент Wikidata → статті в кожному мовному розділі; «статті немає» + кандидати
      → analyze  перегляди (з редиректами, з заповненням нулями) → метрики → вердикт довіри → графіки
      → [LLM] відповідь; числа — лише з виводу команд
      → report   PDF на одну сторінку + перевірка, що всі числа в нотатках агента є в даних
```

| Команда | Для чого |
|---|---|
| `find "<тема>" --langs pl,cs` | кандидати Wikidata з описами, статті по мовах, позначка неоднозначності |
| `analyze Q123 [Q456 …] --langs …` | ріст, рівень, вердикт довіри, порівняння, критерії користувача, графіки |
| `views … --access desktop --totals` | сирі ряди для нестандартних питань (платформи, боти, щоденні дані) |
| `top --lang cs --month 2026-08` | найпопулярніші статті (пошук тем) |
| `report <dir> --notes - <<'EOF' … EOF` | PDF-звіт |

**Ключові рішення** (детально — [docs/decisions.md](docs/decisions.md)):
- **Відносний ріст — головна метрика.** Це зміна частки теми серед усіх переглядів мовного розділу. Людських переглядів Вікіпедії у 2025 стало на ~8% менше, тож сирі перегляди змішують інтерес до теми з падінням платформи. Абсолютний ріст показано поруч.
- **Довіра — прозорі правила, а не «скор».** Обсяг, ширина інтервалу, залежність від сплесків, стійкість до варіантів аналізу (без сплесків, вікно на 6 місяців раніше, без редиректів), нова чи перейменована стаття.
- **Відсутня стаття = «не вимірюється».** Відсутність статті не означає «нуль інтересу». Про інтервальне голодування немає польської статті, і навичка каже це прямо.
- **Коректний клієнт API.** User-Agent з контактом, не більше 3 запитів на секунду і 3 паралельних, повтори з урахуванням `Retry-After`.
- **SQLite-кеш.** Уточнення завантажують лише дні, яких ще немає в кеші.

Специфікація — [docs/SPEC.md](docs/SPEC.md), методологія — [references/methodology.md](references/methodology.md).

## Як навичка допомагає перевіряти висновки

1. **Вердикт довіри High/Medium/Low з причинами** для кожного ряду.
2. **Аналіз чутливості.** Висновок перераховується в кількох варіантах. Для порівнянь окремо видно, чи зберігається лідер і чи перетинаються інтервали.
3. **Числа з даних.** Агент не рахує сам. PDF не збирається, якщо в нотатках агента є число, якого немає в результатах.
4. **Явні застереження:** інтерес ≠ готовність платити; мова ≠ країна; статті — це проксі; дата сплеску не пояснює його причину; попередження про перекласифікацію ботів у 2025 році.
5. **Прозорість даних:** які статті виміряно, вікно, команда для відтворення у футері PDF.

## Якість: evals

Критерії прийняття зафіксовано до реалізації — [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md).

- **Робочий набір** (~60 питань + діалоги) згенерував окремий агент за [таксономією простору питань](evals/taxonomy.md).
- **Прихований набір** (44 питання) написав інший агент, який бачив лише текст умови. Розробник його не бачив до фінального прогону, SHA-256 зафіксовано заздалегідь.
- **Оцінювання:** універсальні автоматичні перевірки і LLM-суддя з рубрикою та цитатами. Базова лінія — Haiku без навички.

## Обмеження

- Перегляди Вікіпедії — це інформаційний інтерес, не попит і не готовність платити.
- Мовний розділ — не країна.
- Тема вимірюється через конкретні статті; якщо статті немає в розділі, тема там не вимірюється.
- Дані — з липня 2015 року до вчора; причини сплесків не визначаються.
- У PDF підтримуються латиниця, кирилиця, грецька і в'єтнамська. CJK, арабське письмо й деванагарі замінюються на «?» з попередженням; відповідь у чаті це обмеження не зачіпає.
- REST API розрахований на десятки статей. Сотні й тисячі — у [roadmap](docs/roadmap.md).

## Структура

```
SKILL.md                інструкції для агента (завантажується при активації)
scripts/wiki.py         CLI (PEP 723 + lock-файл); код у scripts/wikiinterest/
references/             методологія й нотатки про дані (агент читає за потреби)
assets/                 підписи PDF (en/uk)
tests/                  pytest: ядро, графіки/PDF, структура, живі звірки з API (WIKI_LIVE=1)
evals/                  таксономія, розмітка, набори питань, запускач, оцінювач, результати
docs/                   специфікація, критерії прийняття, рішення, перевірка, roadmap
```

Тести: `uv run --with-requirements tests/requirements.txt pytest tests` (живі звірки: `WIKI_LIVE=1`).
